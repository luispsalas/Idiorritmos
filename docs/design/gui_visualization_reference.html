IDIORRITMOS — signal visualization reference

Tier-2 JUCE GUI concept sketch · synthetic data, design reference only · not the shipping UI

EVOLVE FREEZE taps 12 · fbk 0.6
1 · Input vs. Output — overlay scopeFREE juce::AudioVisualiserComponent · dry-in + final-out, sample-accurate
Input (dry source)   Output (texture bloom) — the mc.scope~ analog. Both signals exist at the JUCE processBlock boundary, so this needs no engine change.
2 · Stereo field — goniometervia outport data custom Path / foleys
Plots L against R. A mono source enters as a vertical line; the taps fan it into width. The clearest read on the stereo space the engine builds — try Placement → Scatter.
3 · Tap constellationvia outport data delay×pan×level
Each dot = one delay tap: X = delay time, Y = pan, size/brightness = level. Draws the Gait directly — switch modes and watch the pattern reshape; Evolve drifts it; Freeze holds it.
4 · Support readoutsvia outport data juce::dsp::FFT · ff_meters
Spectrum — see the harmonic fattening from Cloud + Diffusion. Alongside it in the real UI: an Everlast energy meter (how alive the feedback is) and a Freeze lamp — both cheap scalar outports.
What's reachable: only dry input + final output are sample-accurate at the JUCE layer (panel 1, free). Everything internal — per-tap level/pan, wet/dry RMS, feedback energy, freeze state — must be emitted from gen as control-rate outport data (~30 Hz), since a stereo Effect can't add audio metering channels. That one additive engine change (no param-set change, no DSP refactor) unlocks panels 2–4. Draw from a lock-free FIFO on a message-thread Timer — never from the audio thread.
